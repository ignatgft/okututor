# Руководство по разработке (CONTRIBUTING)

## 🌿 Модель ветвления Git

В проекте используется модель на основе Git Flow с защитой производственных веток:

```
main (production) ──────────────────────────────● (v0.1.0)
       ▲
       │ Pull Request (после регрессионного тестирования)
develop (integration) ──●─────────●─────────────●
                          \       /
             feature/tutor \─────/
```

- **`main`**: Защищённая ветка продакшена. Любые прямые пуши и `git push --force` запрещены. Релизы попадают сюда только через проверенные Pull Request.
- **`develop`**: Основная ветка интеграции. Сюда стекаются готовые фичи и фиксы.
- **`release/backend`**, **`release/frontend`**: Ветки стабилизации перед выкаткой в прод.
- **`feature/*`**: Ветки разработки новой функциональности (ответвляются от `develop`).
- **`fix/*`**: Ветки точечных исправлений ошибок.
- **`audit/*`**: Ветки аудитов, структурного рефакторинга и стабилизации кодовой базы.

## 📝 Регламент коммитов (Conventional Commits)

Формат сообщений коммитов строго следует спецификации Conventional Commits:

```
<тип>(<область>): <краткое описание в повелительном наклонении>

[опциональное тело с деталями]
```

### Основные типы:
- `feat`: Новая функциональность
- `fix`: Исправление ошибки (с обязательным регрессионным тестом)
- `refactor`: Рефакторинг кода без изменения логики
- `docs`: Изменения в документации
- `test`: Добавление или обновление тестов
- `chore`: Обновление сборки, зависимостей, конфигураций

Примеры:
```bash
git commit -m "fix(tutor): enforce strict expiresAt check in repository queries"
git commit -m "feat(monitoring): add stalled expiry scheduler alert rule"
```

## 🔒 Ключевые архитектурные правила

1. **Free MVP:** Проект полностью бесплатен для репетиторов и учеников. Никаких платных тарифов, VIP-статусов, платных поднятий резюме или скрытых подписок.
2. **Единая сущность резюме:** Сущность `TutorProfile` является единственным источником правды для резюме в БД (`user_id` уникален). Запрещено создавать параллельные сущности или таблицы заявок.
3. **Строгий фильтр активности:** Любая публичная выдача (поиск, фильтры, каталог, sitemap) обязана строго фильтровать по `expiresAt > current_timestamp`.
4. **Безопасность и секреты:** Никаких секретов, паролей или токенов в кодовой базе. Все конфигурации передаются через переменные окружения (`.env.example` как шаблон).
5. **Тестирование:** Каждый исправленный дефект должен сопровождаться юнит-тестом на регрессию.

## ✅ Чек-лист перед Pull Request

- [ ] Код компилируется без ошибок (`mvn test-compile`, `npm run build`).
- [ ] Все тесты проходят успешно (`mvn test`, `npm test`).
- [ ] В коде отсутствуют секреты и hardcoded-пароли.
- [ ] Создана новая ветка от `develop` (не `main`).
- [ ] Сообщение коммита оформлено по конвенции Conventional Commits.
