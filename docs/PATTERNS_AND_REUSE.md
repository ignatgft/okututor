# Паттерны проектирования и переиспользование

## Общие правила
- Одна задача — одна реализация. Перед новым классом или компонентом поищи существующий (grep по имени, по домену).
- Переиспользуй, а не копируй. Копия в двух местах — повод вынести общее.
- Не вводи новые паттерны без ADR, если текущий уже решает задачу.

## Backend (Spring Boot)
- Слои: controller → service → repository. Контроллеры без бизнес-логики.
- DTO и маппинг: request/response DTO отдельно от сущностей. Маппперы в одном месте (MapStruct или выделенные класс-мапперы).
- Транзакции: @Transactional на уровне service, не в контроллере.
- Общие фильтры и условия поиска — в одном месте (например, спецификация или общий метод репозитория с expiresAt > now), а не в каждом запросе отдельно.
- Ошибки: единый @RestControllerAdvice, единый формат ответа.
- Авторизация: @PreAuthorize и проверка владельца в сервисе, а не в контроллере вручную.
- Фоновые задачи: один @Scheduled-компонент, идемпотентные SQL-обновления.
- Уведомления: только через NotificationService, без прямых вызовов почты из доменных сервисов.
- Strategy — для разных способов поиска или уведомлений, но не для одного варианта.
- Template method / базовый класс — для повторяющихся шагов сервисов, если их три и более.

## Frontend (React + TypeScript)
- Компоненты: презентационные (UI) отдельно от контейнеров (данные и запросы).
- Общие UI-компоненты — в одном месте (кнопки, карточки статусов, бейджи, модалки). Не дублировать.
- Данные с сервера — только через TanStack Query и общий API-слой (api/marketplace/*). Не делать fetch в компонентах.
- Глобальное состояние — Zustand, только для того, что реально глобально (сессия, тема, язык). Не дублировать состояние сервера в Zustand.
- Статусы резюме — один компонент ResumeStatusCard и один хук для вычисления статуса EXPIRING/EXPIRED по expiresAt.
- Формы: одна схема валидации на поле, переиспользуемая между мастером и редактированием.
- i18n: тексты только через i18next, без захардкоженных строк в компонентах.
- Токены дизайна: tokens.css, цвета только через переменные, светлая и тёмная тема через [data-theme="dark"].
- Маршруты: один источник конфигурации React Router.

## Общие принципы
- Композиция важнее наследования.
- Конфигурация в одном месте (application.yml / .env).
- Константы статусов и ролей — одна точка (enum на бэке, зеркало в типах на фронте, генерируется или проверяется тестом).
- Тесты: тест на регрессию при каждом исправлении бага.

## Как проверить дубли
- Backend: grep по имени метода и по SQL-условиям; поиск похожих сервисов по домену.
- Frontend: поиск по похожим именам компонентов и хуков; поиск одинаковых fetch-вызовов.
- Зафиксировать в AUDIT_REPORT: канонический вариант, дубли, план слияния.
