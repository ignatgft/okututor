# Product scope and decisions — OkuTutor Free Marketplace MVP

## Product definition

OkuTutor — бесплатная площадка для поиска репетиторов в Кыргызстане. Пользователь фильтрует анкеты и отправляет обращение; преподаватель размещает одну анкету, проходит ручную модерацию и принимает обращения. `USER` может выполнять обе функции в одном аккаунте.

## Цели запуска
1. Найти реального преподавателя по предмету/локации/формату/бюджету.
2. Понять предложение на основании реальных полей анкеты.
3. Отправить обращение и знать, что оно принято.
4. Владелец анкеты видит входящие обращения и может их обработать.
5. Преподаватель создаёт/редактирует анкету, отправляет на модерацию и видит статус.
6. Администратор безопасно одобряет/отклоняет/приостанавливает анкету, управляет пользователями и поддержкой.
7. Продукт работает, мониторится, защищает PII и имеет проверяемый релизный процесс.

## Вне MVP
- Платные планы/подписки, комиссия, платежи, billing.
- Курсы, покупка курсов, enrollment, lessons, bookings, scheduling, recurring lessons.
- Homework, student progress, attendance, video rooms/LiveKit.
- Рейтинг/отзывы репетитора без доказуемого workflow, связанного с `TutorProfile` и завершённым реальным взаимодействием.
- Избранное, пока нет полноценного backend storage/API/owner checks.
- Сложная CRM, автоматические кампании, recommendation engine.
- Автоматическое истечение/продление/поднятие анкеты: в текущем enum нет `EXPIRED`/`HIDDEN`, это не нужно придумывать для запуска.

## Продуктовые решения

### PD-001 — один USER
Наличие анкеты не меняет роль. Новые сценарии используют USER/ADMIN/SUPER_ADMIN. Старые STUDENT/TUTOR/TEACHER поддерживаются только для совместимости.

### PD-002 — TutorProfile canonical
`tutor_profiles` и `TutorProfile` — источник истины. `TutorApplication` — legacy, не участвует в новом marketplace create/edit/moderation.

### PD-003 — данные только правдивые
Публичная карточка не выдумывает рейтинг, review count, образование, достижения, цену, опыт и verified badge. Если значения нет, поле не показывается. Текущая сущность `TutorProfile` имеет default `rating=4.9`, но Review API на baseline относится к Course/Booking: это нельзя выдавать за реальный tutor rating.

### PD-004 — единый контактный сценарий
Основное действие — форма «Связаться/Оставить заявку» и `TutorRequest`. Гость может отправить форму, если локальный аудит подтвердит rate limit, приватность и UX. Авторизованный пользователь видит исходящую заявку; владелец профиля — входящую. Чат допустим только как request-linked продолжение после E2E проверки; сбой чата не отменяет созданную заявку.

### PD-005 — бесплатно
Нет оплаты, подписок, выручки и платного продвижения. Не показывать такие показатели в админке.

### PD-006 — обязательная модерация
Новая анкета проходит `DRAFT → PENDING_MODERATION → PUBLISHED/REJECTED`. Только backend admin action может опубликовать. `SUSPENDED` — административная приостановка.

### PD-007 — legacy не удалять вслепую
Старые модули/данные можно оставить dormant для совместимости. Сначала убрать из основной навигации и остановить новые записи; удалять только при доказанной ненужности, оценке данных, миграции, backup и rollback.

## Вопросы локального аудита для решения с минимальным scope
- Как формировать public display name: firstName+lastName или user.fullName?
- Какие поля можно менять у PUBLISHED анкеты без повторной модерации? Baseline `TutorProfileService.update()` разрешает update PUBLISHED и оставляет статус PUBLISHED. Зафиксировать риск и решение.
- Оставить in-app chat после request или пока только request/contact details? Оставлять чат только при доказанной безопасности/UX.
- Какой avatar endpoint можно использовать для TutorProfile? Не считать filename загрузкой.
- Support attachments — только если реальный upload and ownership checks.
- Какие legal documents реально утверждены юристом? Генерированный текст не обозначать юридически одобренным.
