# OkuTutor — автономный пакет доведения до рабочего Marketplace MVP

Пакет предназначен для Antigravity и локального клона `ignatgft/okututor`.

## Запуск
1. Открой корень локального репозитория в Antigravity.
2. Проверь `git status` и сохрани свои незакоммиченные изменения.
3. Скопируй содержимое архива в корень репозитория с сохранением структуры.
4. Передай Antigravity целиком `MASTER_EXECUTION_TASK.md` и запусти большую многоэтапную работу через `/teamwork`. Для независимого первоначального аудита допустим `/swarm`, затем нужен один ответственный интегратор.
5. Агент обязан прочитать `AGENTS.md`, функциональный каталог, карту маршрутов, исходный аудит и все правила `.agents/rules/`.

## Назначение пакета
Пакет определяет продуктовый scope, страницы, формы, кнопки, API-поведение, роли, статусы, тест-сценарии, администрирование, мониторинг, структуру репозитория и Git-процессы. Он рассчитан не на генерацию TODO, а на автономное исправление и доведение реальных сценариев до проверенного состояния.

## Важное ограничение аудита
Исходники ветки `master` проверены через GitHub на commit `54eca9583381384ba0c966fa9386c713b7ad5de4`. Это статический аудит. Приложение локально не запускалось, браузерные клики и команды тестов не выполнялись. Поэтому обнаруженные проблемы надо подтвердить в локальном окружении, а непроверенные тесты отмечать `NOT RUN` или `BLOCKED`, не `PASSED`.

## Главные документы
- `MASTER_EXECUTION_TASK.md` — единая большая задача для Antigravity.
- `MVP_FUNCTIONAL_CATALOG.md` — что должна делать каждая MVP-страница, кнопка и форма.
- `PAGES_AND_ROUTES_MAP.md` — маршруты, роли, канонические URL и legacy redirects.
- `REPOSITORY_AUDIT_BASELINE.md` — фактическая исходная точка и найденные дефекты.
- `PRODUCT_SCOPE_AND_DECISIONS.md` — продуктовые границы MVP.
- `ADMIN_AND_MONITORING_SPEC.md` — грамотная админка и технический мониторинг.
- `ACCEPTANCE_TEST_SCENARIOS.md` — обязательные проверки пользовательских сценариев.
- `GIT_REPOSITORY_GOVERNANCE.md` — ветки, worktree, PR, CI и безопасный cleanup.
- `.agents/agents/` — роли субагентов; `.agents/rules/` — постоянные правила.

## Главный сценарий MVP
Гость или USER открывает каталог → находит опубликованную анкету → отправляет обращение → владелец анкеты видит входящее обращение → обрабатывает его по согласованному каналу → администратор модерирует анкету и контролирует злоупотребления.

Регистрация, вход, восстановление доступа, редактирование анкеты, личный кабинет, поддержка и безопасные админские действия также должны работать.
